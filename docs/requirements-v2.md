# dsh-todolist v2 需求文档

| 项 | 值 |
|---|---|
| 文档版本 | v1.0（定稿） |
| 目标版本 | dsh-todolist v2.0 |
| 当前基线 | v0.2.1（本地化源码） |
| 状态 | 需求已确认，可进入开发 |
| 范围 | 可配置化改造 + 子任务 + 标签 + 搜索 + 看板 + 提醒 + 导入导出 + AI 工具拆分 |

---

## 1. 背景与目标

### 1.1 现状
现有插件（v0.2.1）是一个**功能全量开启**的待办看板：列表、今日、日历、周、项目五种视图固定存在，所有功能对所有人可见。数据存储在本地 `todos.json`，通过 `todolist` 单一 AI 工具操作。

### 1.2 本次目标
把插件从"固定功能集合"改造为**可配置的待办系统**，同时补齐任务管理的关键能力：

1. **可配置**：每个视图/功能模块独立开关，从"仅一个列表"到"完整看板 + AI + 提醒"自由组合
2. **任务结构化**：主任务-子任务、标签
3. **找得到**：顶部搜索，输入即搜（防抖 300ms），命中高亮
4. **看得清**：按状态或按项目的三列看板，拖拽改状态/项目
5. **记得住**：到期提醒（5 分钟 / 15 分钟 / 1 小时 / 当天 9 点），用 DSH 系统通知
6. **带得走**：JSON / CSV 导出，JSON 导入（迁移、备份）
7. **AI 可控**：现有 `todo_*` 工具默认关闭；新增只读 `todo_search`，按需开启
8. **扛得住**：5000 条任务下列表滚动、搜索、日历渲染流畅

### 1.3 非目标（本期不做）
- 多用户 / 账号体系 / 云端同步
- 多人协作、任务指派与评论
- 跨设备实时同步
- 甘特图、依赖关系图
- 移动端独立 App（沿用 DSH 响应式布局）
- **后台常驻提醒**：提醒仅在 DSH 运行期间生效，DSH 关闭后不补发（已确认）

## 2. 角色与典型场景

| 角色 | 诉求 | 配置档位 |
|---|---|---|
| 极简用户 | 只想记事，不要视图和 AI | `minimal`：仅列表 + 新增/完成 |
| 日常用户 | 列表 + 今日 + 搜索 + 标签 | `standard` |
| 项目型用户 | 看板、项目分组、子任务、提醒 | `full` |
| AI 协作用户 | 只允许 AI 查询，不允许改数据 | `full` + `ai.search.enabled`，`ai.write.enabled=false` |

## 3. 功能配置体系（核心）

### 3.1 设计原则
- **一切可关**：除"列表"外，所有模块默认值可被覆盖，关闭后不渲染任何入口、不注册相关逻辑
- **配置即数据**：配置与任务数据同源存储，随导入导出迁移
- **热生效**：保存配置后立即重建界面，无需重启 DSH
- **降级安全**：非法配置值回退默认值并记录告警，不阻断插件加载

### 3.2 模块矩阵

| ID | 模块 | 类型 | 默认 | 依赖 | 说明 |
|---|---|---|---|---|---|
| `core.list` | 待办列表 | 视图 | **强制开启** | — | 插件根基，不可关闭 |
| `view.done` | 已办 | 视图 | 开 | — | 已完成/已取消集中展示；**关闭后已完成回列表置底** |
| `core.search` | 顶部搜索 | 功能 | 开 | — | 防抖 300ms |
| `view.today` | 今日 | 视图 | 开 | — | 逾期/今日到期/周期 |
| `view.calendar` | 日历 | 视图 | 开 | — | 月视图 |
| `view.week` | 周视图 | 视图 | 开 | — | 周泳道 |
| `view.project` | 项目看板 | 视图 | 开 | — | 横向项目列 |
| `view.board` | 三列看板 | 视图 | 开 | — | 状态/项目两种分组 |
| `feature.subtask` | 子任务 | 功能 | 开 | — | 一层子任务 |
| `feature.tags` | 标签 | 功能 | 开 | — | 多标签 |
| `feature.reminder` | 到期提醒 | 功能 | 开 | 系统通知 | 首次需要时惰性请求通知权限 |
| `feature.importExport` | 导入导出 | 功能 | 开 | — | JSON/CSV |
| `ai.write` | AI 写操作工具 | 能力 | **关** | — | `todo_*` |
| `ai.search` | AI 只读查询 | 能力 | **关** | — | `todo_search` |

### 3.3 预设档位

| 预设 | 包含模块 |
|---|---|
| `minimal` 极简 | `core.list`（已完成置底，因 `view.done` 关闭） |
| `standard` 标准 | `core.list` `view.done` `core.search` `view.today` `feature.subtask` `feature.tags` `feature.importExport` |
| `full` 完整 | 全部视图与功能（`ai.*` 仍需手动开启） |

> 预设只是"一键勾选"，选择后仍可逐项微调；微调后档位显示为「自定义」。

| 配置键 | 类型 | 默认 | 约束 | 说明 |
|---|---|---|---|---|

| `search.debounceMs` | int | 300 | 100–1000 | 搜索防抖 |
| `search.scope` | enum | `all` | all/title/tag | 搜索范围 |

| `board.columns` | enum | `3` | 3 | 状态分组固定三列 |
| `subtask.maxDepth` | int | 1 | 固定 1 | 子任务层级 |
| `tags.maxPerTask` | int | 8 | 1–20 | 单任务标签上限 |
| `tags.maxLength` | int | 20 | 1–50 | 单个标签长度 |
| `reminder.offsets` | int[] | `[5,15,60]` | 5/15/60/540 | 分钟；540=当天9点 |
| `reminder.quietHours` | string | null | `HH:MM-HH:MM` | 免打扰区间 |

| `perf.virtualThreshold` | int | 200 | 50–2000 | 超过该条数启用虚拟滚动 |
| `ai.write.enabled` | bool | false | — | `todo_*` 工具注册开关 |
| `ai.search.enabled` | bool | false | — | `todo_search` 工具注册开关 |

### 3.5 配置界面
- **入口**：待办面板右上角「⚙ 设置」
- **布局**：左侧模块开关列表，右侧详细参数（随选中模块变化）
- **交互**：改动即时预览，底部「保存」/「取消」；保存后整体重建视图
- **提示**：开启 `ai.write` 时弹出二次确认（一句话说明"AI 将可以新增、修改、删除你的任务"）；开启 `feature.reminder` 时请求通知权限

### 3.6 存储与迁移
- 配置存放于 `todos.json` 同目录的 `config.json`（与任务分离，便于单独备份）
- 缺少字段 → 用默认值补齐；未知字段 → 保留但忽略
- v0.2.1 数据升级：任务补齐 `parentId=null`、`tags=[]`、`dueTime=null`

## 4. 数据模型

### 4.1 任务（Task）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string(8 hex) | 是 | 主键 |
| `text` | string | 是 | 任务标题，首行为标题；≤ 500 字 |
| `desc` | string | 否 | 详细描述，≤ 5000 字 |
| `status` | enum | 是 | pending / doing / done / blocked / cancelled |
| `parentId` | string\|null | 否 | 父任务 id；仅一层 |
| `tags` | string[] | 否 | 标签，去重，受 `tags.max*` 约束 |
| `proj` | string\|null | 否 | 项目名（自由文本，作为分组维度） |
| `who` | string\|null | 否 | 负责人 |
| `quadrant` | q1..q4\|null | 否 | 四象限 |
| `start` | YYYY-MM-DD\|null | 否 | 开始日期 |
| `due` | YYYY-MM-DD\|null | 否 | 截止日期 |
| `dueTime` | HH:MM\|null | 否 | 截止时间（提醒用；为空按 23:59 计） |
| `repeat` | daily/weekly/monthly\|null | 否 | 周期 |
| `on` | int\|null | 否 | 周期定点（weekly 1-7 / monthly 1-31） |
| `doneAt` | ISO datetime\|null | 否 | 完成时间（状态置 done 时写入；恢复时清空） |
| `createdAt` | ISO datetime | 是 | 创建时间 |
| `updatedAt` | ISO datetime | 是 | 更新时间 |
| `order` | number | 否 | 看板/列表手动排序位 |
| `reminder.sent` | Record<offset, ISO datetime> | 否 | 已发送提醒记录（去重） |

### 4.2 子任务规则
1. **仅一层**：`parentId` 只能指向顶层任务；子任务不能再有子任务（服务端拒绝，返回错误）
2. **独立字段**：子任务有自己的 `status`、`due`、`tags`，不继承父任务
3. **父任务展示**：列表/看板中父任务显示 `3/5` 形式的子任务完成进度
4. **状态聚合**：父任务自身状态不因全部子任务完成而自动改变（避免误判），但可选择开启"子任务全部完成时自动完成父任务"（默认关）
5. **删除**：删除父任务时级联删除子任务，需二次确认并提示子任务数量
6. **视图归属（已确认）**：子任务**不独立出现在任何视图**（列表、看板、日历、周、今日、已办均不单独成行），只在父任务详情弹窗中展示明细，并在明细内直接勾选完成/恢复
7. **完成父任务**：父任务标为完成时，未完成子任务保持原状（不级联完成），在详情中提示；父任务进入「已办」后子任务明细仍可查看

### 4.3 标签规则
1. 自由文本，去空、去重、大小写不敏感（`Work` 与 `work` 视为同一标签，存储保留首次输入形式）
2. 单个任务标签数 ≤ `tags.maxPerTask`，单标签长度 ≤ `tags.maxLength`
3. 输入时提供已有标签自动补全（按使用频次排序）
4. 支持按标签筛选（多选，OR 语义）
5. **标签无颜色（已确认，本期不做）**，统一中性 chip 展示，不引入用户自选色

### 4.4 存储
| 项 | 值 |
|---|---|
| 任务文件 | `<DSH_HOME>/todo-data/todos.json` |
| 配置文件 | `<DSH_HOME>/todo-data/config.json` |
| 写入 | 原子写（tmp + rename），写操作 500ms 合并节流 |
| 容量目标 | 5000 条 ≤ 10 MB |
| 备份 | 每次导入前自动快照 `todos-backup-<timestamp>.json`，保留最近 5 份 |

## 5. 功能详细需求

### FR-1 配置化（对应 3.x）
- **FR-1.1** 未启用模块不渲染入口、不加载对应代码路径（看板/日历关闭时不注册渲染函数）
- **FR-1.2** 关闭 `core.search` 后顶部搜索框消失，快捷键不响应
- **FR-1.3** 保存配置后界面立即按新配置重建，保留当前筛选条件（若对应模块已关闭则重置）
- **FR-1.4** 配置非法时回退默认并提示一次

### FR-2 列表（`core.list`）
- **FR-2.1** 未完成任务按「逾期 → 截止日期 → 创建时间」排序
- **FR-2.2** **已完成/已取消任务的归属（已确认）**：
  - `view.done` 开启 → 从列表移出，集中到「已办」视图
  - `view.done` 关闭 → 保留在列表末尾灰显置底（最简模式下的兜底）
- **FR-2.3** 勾选框完成/恢复；父任务行显示子任务进度（如 `1/3`）
- **FR-2.4** 点击行打开详情；子任务仅在详情内增删改与勾选，不单独成行
- **FR-2.5** 空态区分「无任务」与「筛选后无结果」

### FR-3 搜索（`core.search`）
- **FR-3.1** 位置：待办面板顶部，占一整行；占位符「搜索任务、标签、项目…」
- **FR-3.2** 输入即搜，**防抖 300ms**（可配置）；空输入立即恢复原列表
- **FR-3.3** 匹配范围：标题、描述、标签、项目名、子任务标题；大小写不敏感
- **FR-3.4** **命中高亮**：列表中用 `<mark>` 标出匹配片段，多词查询各自高亮
- **FR-3.5** 多关键词以空格分隔，**AND** 语义；支持 `#标签` 精确匹配标签、`@项目` 匹配项目
- **FR-3.6** 与现有筛选（状态、四象限、项目）叠加生效
- **FR-3.7** 显示结果计数「找到 N 条」；无结果展示空态并提示清除条件
- **FR-3.8** `Esc` 或「×」清空搜索；清空后焦点回到输入框
- **FR-3.9** 搜索不改变任务数据，不触发写盘

### FR-4 三列看板（`view.board`）
- **FR-4.1** 分组维度可切换：
  - **按状态**：待办（pending）/ 进行中（doing）/ 已完成（done）三列；`blocked`、`cancelled` 按配置归入待办列或独立列（默认归入待办列并标注）
  - **按项目**：每个 `proj` 一列 + 「未分类」列，列顺序可拖拽保存
- **FR-4.2** 卡片内容：标题、标签 chip、截止日期（逾期红色）、子任务进度、负责人
- **FR-4.3** **拖拽改状态/项目**：拖到目标列即修改对应字段并持久化；失败回滚并提示
- **FR-4.4** 列内拖拽排序，写入 `order`；刷新后保持
- **FR-4.5** 键盘替代：卡片聚焦后 `Alt+←/→` 移动到相邻列，`Alt+↑/↓` 调整顺序（可访问性要求）
- **FR-4.6** 列头显示计数；列可折叠
- **FR-4.7** 5000 条时仅渲染可见列卡片（横向虚拟化，可配置 `perf.VirtualList`）

### FR-5 子任务（`feature.subtask`）
- **FR-5.1** 详情弹窗内「＋ 添加子任务」，回车追加
- **FR-5.2** 子任务行支持勾选完成/恢复、编辑标题、删除、设置自己的截止日期
- **FR-5.3** 父任务列表行显示 `已完成/总数` 进度（微型进度条 + 数字）
- **FR-5.4** 禁止对子任务再次添加子任务（入口隐藏 + 服务端校验）
- **FR-5.5** 删除父任务需二次确认，提示「将同时删除 N 个子任务」
- **FR-5.6** 子任务不出现在列表/看板/日历/今日/已办任何视图中（仅父任务明细，已确认）
- **FR-5.7** 父任务已完成进入「已办」后，明细仍可查看与勾选

### FR-6 标签（`feature.tags`）
- **FR-6.1** 详情弹窗内标签输入：输入后回车成 chip，`Backspace` 删除最后一个
- **FR-6.2** 自动补全下拉：已有标签按频次排序
- **FR-6.3** 列表/卡片展示标签 chip（超出数量折叠为 `+N`）
- **FR-6.4** 标签筛选器：多选，OR 语义；与搜索、状态筛选叠加
- **FR-6.5** 标签重命名（全局替换）与删除（从所有任务移除），需二次确认

### FR-7 到期提醒（`feature.reminder`）
- **FR-7.1** 提醒时机可多选：**提前 5 分钟 / 15 分钟 / 1 小时 / 当天 9 点**
- **FR-7.2** 计算基准：`due` + `dueTime`（无 `dueTime` 按 23:59）；无 `due` 的任务不提醒
- **FR-7.3** 触发通道优先级：
  1. DSH Desktop 原生系统通知（应用在前台或后台都可用）
  2. 浏览器 `Notification` API（需用户授权）
  3. 应用内 toast（前两者不可用或用户拒绝时）
- **FR-7.4** 通知内容：任务标题、剩余时间（如「还有 15 分钟到期」）、所属项目；点击通知聚焦到该任务详情
- **FR-7.5** **去重**：同一任务的同一提醒点只发送一次，记录在 `reminder.sent`；任务 `due` 变更后重置
- **FR-7.6** **免打扰**：`quietHours` 内不发通知，顺延到结束后第一条；可关闭
- **FR-7.7** **合并**：同一分钟内多条提醒合并为「3 个任务即将到期」摘要，点击展开列表
- **FR-7.8** 周期任务：仅在每次到期时提醒一次（按当前周期实例）
- **FR-7.9** 权限被拒绝时，设置页显示一次性引导，可重新请求
- **FR-7.10** **运行期限制（已确认）**：提醒只依赖 DSH 进程内的定时调度，DSH 关闭期间不计算、不补发；重新打开后仅对"仍未过期"的提醒点补发一次

### FR-8 导入导出（`feature.importExport`）
- **FR-8.1** **导出 JSON**：`{ schemaVersion, exportedAt, config, tasks[] }`，含子任务与标签、提醒记录
- **FR-8.2** **导出 CSV**：UTF-8（可选 BOM），列：`id,parentId,text,desc,status,tags,proj,who,quadrant,start,due,dueTime,repeat,on,doneAt,createdAt,updatedAt`；标签以 `|` 分隔；子任务单独成行并通过 `parentId` 关联
- **FR-8.3** **导入 JSON**：
  - 校验 `schemaVersion` 与必填字段；单条非法 → 跳过并汇总报告，整体不中断
  - 模式：**合并**（按 id 去重，冲突以导入文件为准） / **替换**（清空后导入，需二次确认）
  - 导入前预览：总条数、新增数、覆盖数、将跳过的非法条数
  - 导入前自动备份；导入失败原子回滚
- **FR-8.4** 支持导入 v0.2.1 旧格式（自动补默认字段）
- **FR-8.5** 导出/导入完成后提示耗时与条数

### FR-9 AI 工具（`ai.write` / `ai.search`）
- **FR-9.1** 现有写工具拆分为 `todo_*` 并**默认关闭**：
  | 工具 | 能力 |
  |---|---|
  | `todo_add` | 新增任务/子任务 |
  | `todo_update` | 修改字段（含标签、项目、截止） |
  | `todo_done` | 完成/恢复 |
  | `todo_remove` | 删除（父任务级联需显式 `cascade:true`） |
  | `todo_list` | 列表查询（写工具开关的附属） |
- **FR-9.2** **新增 `todo_search`（只读）**，默认关闭，独立开关：
  - 入参：`query`（关键词）、`status`、`proj`、`tag`、`dueBefore`、`dueAfter`、`includeSubtasks`、`limit`（默认 20，上限 100）
  - 出参：`{ total, items:[{id,text,status,proj,tags,due,dueTime,parentId}] }`
  - **保证**：无任何写入副作用；不触发提醒；不修改 `updatedAt`
- **FR-9.3** 开关关闭时工具**不注册**（MCP 工具列表中不存在），而非注册后拒绝
- **FR-9.4** 开启 `ai.write` 需二次确认；设置页常驻提示「AI 可修改你的任务」
- **FR-9.5** 所有 AI 写操作记录审计日志（`<dataDir>/ai-audit.log`，滚动保留 1000 行），可在设置页查看

## 6. 非功能需求

### NFR-1 性能（5000 条任务基准）
| 指标 | 目标 |
|---|---|
| 首屏渲染（列表 5000 条） | ≤ 1000 ms（虚拟列表 ≤ 500 ms） |
| 搜索响应（防抖后） | ≤ 100 ms |
| 滚动帧率 | ≥ 50 fps（无卡顿） |
| 日历月视图渲染/切换 | ≤ 300 ms |
| 看板拖拽响应 | ≤ 50 ms 视觉反馈 |
| 单次写盘 | ≤ 50 ms（节流合并后） |
| 内存占用 | ≤ 100 MB |

- 虚拟列表为可选能力，超过 `perf.virtualThreshold` 自动启用（若开启）

### NFR-2 兼容性
- DSH Web 与 DSH Desktop（Electron）均可运行
- 深浅色主题跟随 DSH token（`--dsw-*`），不硬编码颜色
- 窗口宽度 ≥ 360px 可用；窄屏工具栏横向滚动不撑破布局

### NFR-3 可访问性
- 全键盘可达：Tab 进入、方向键导航、Enter 编辑、Esc 关闭
- 勾选框/按钮有 `aria-label`；看板拖拽有键盘等价操作
- 颜色对比度 ≥ WCAG AA；逾期/状态不以颜色为唯一信息载体

### NFR-4 国际化
- 中英文双语，文案全部走 i18n 字典，不硬编码
- 日期格式按 locale 显示，存储统一 `YYYY-MM-DD`

### NFR-5 健壮性
- 存储文件损坏 → 启动时回退最近备份并提示，不丢全部数据
- 并发写 → 串行队列，避免覆盖
- 所有异步操作有失败提示与回滚

## 8. 验收标准（AC）

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| AC-1 | 最简模式 | 配置为 `minimal` 时，界面只有一个列表和新增按钮；顶部无搜索、无视图切换；已完成任务在列表末尾灰显置底 |
| AC-2 | 完整模式 | `full` 时所有启用的视图可用，标签/子任务/导入导出入口齐全 |
| AC-3 | 配置热生效 | 关闭某视图后立即消失，刷新后保持 |
| AC-4 | 子任务 | 新建 3 个子任务，父任务显示 `1/3`；子任务不在列表/看板/日历单独成行；子任务不能建子任务 |
| AC-5 | 标签 | 单任务最多 8 个标签，重复标签被去重；按标签筛选正确 |
| AC-6 | 搜索防抖 | 输入 5 个字符只触发 1 次查询；结果按 300ms 延迟出现 |
| AC-7 | 搜索高亮 | 命中词在列表中高亮显示，多个关键词分别高亮 |
| AC-8 | 看板拖拽 | 卡片拖到「进行中」列后状态变为 doing，刷新后保持 |
| AC-9 | 看板分组切换 | 切到「按项目」后每项目一列，拖拽可改 `proj` |
| AC-10 | 提醒 | 设置 dueTime 为 5 分钟后，到点收到 1 条通知；不重复发送 |
| AC-11 | 免打扰 | quietHours 内不弹通知，结束后补发 |
| AC-12 | 导出 JSON | 导出文件可被同一版本导入，任务数一致 |
| AC-13 | 导出 CSV | Excel 打开中文不乱码，子任务行 parentId 正确 |
| AC-14 | 导入合并 | 同 id 任务被覆盖，其余保留；预览数字准确 |
| AC-15 | 导入回滚 | 故意构造非法文件，导入失败后任务数据与导入前完全一致 |
| AC-16 | AI 工具默认关闭 | 默认配置下 MCP 工具列表无 `todo_*`、无 `todo_search` |
| AC-17 | AI 只读 | 开启 `todo_search` 后调用只能查询，任何写操作被拒绝 |
| AC-18 | 性能 | 导入 5000 条后，首屏 ≤1s、搜索 ≤100ms、滚动无明显卡顿 |
| AC-19 | 旧数据兼容 | v0.2.1 的 todos.json 可直接加载，字段自动补全 |
| AC-20 | 存储损坏恢复 | 人为破坏 JSON，启动后从备份恢复并提示 |
| AC-21 | 已办归属 | 完成一条任务后：`view.done` 开 → 只出现在已办；关闭 → 回列表末尾灰显 |
| AC-22 | 提醒运行期 | 关闭 DSH 期间到点的提醒不补发；重开后仅对未过期提醒点补发一次 |

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| DSH 通知接入点不确定 | 提醒无法落地 | M0 先确认；提供 Web Notification 降级，保证功能可用 |
| 5000 条 JSON 全量读写 | 写延迟、内存上涨 | 节流合并 + 原子写；预留按任务分文件存储的扩展点 |
| 看板拖拽与现有项目视图语义重叠 | 用户困惑 | `view.board` 与 `view.project` 独立开关，默认都在但可在配置中二选一 |
| 子任务出现在看板/日历造成噪音 | 信息过载 | 默认不单独展示，仅父任务聚合进度 |
| 配置项过多导致设置页复杂 | 学习成本 | 三层结构：档位预设 → 模块开关 → 高级参数（默认折叠） |
| 旧数据迁移出错 | 数据丢失 | 迁移前自动备份，失败回滚并保留原文件 |

1. **提醒默认开启**：为让「完整」档位自洽，`feature.reminder` 默认开；通知权限在首次需要时惰性请求，未授权前不打扰。

4. **系统通知通道**：使用浏览器/Electron `Notification`，未直接调用 DSH 桌面原生通知 API（无公开插件接口）。
