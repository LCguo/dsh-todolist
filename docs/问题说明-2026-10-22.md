## 一、已经暴露给你的问题（P0）

### P0-1 待办界面白屏：`Cannot access 'moduleOn' before initialization`

| 项 | 内容 |
|---|---|
| 现象 | 打开待办面板直接渲染报错，界面不可用 |
| 原因 | `moduleOn` 用 `const` 声明在组件体中段，但更靠前的常量（`canEditSubtasks`、`tagsEnabled`）在组件体执行时就调用了它 → 暂时性死区（TDZ） |
| 引入版本 | v2 实现期间（M1 配置体系引入 `moduleOn`，M3/M4 增加前置调用点） |
| 修复 | `1c42df2`：改为函数声明（提升），直接读 `cfg` |
| 遗漏原因 | 自测只覆盖服务端与 i18n，`smoke-client.mjs` 当时只执行 `apply()`，没有执行组件体，因此测试全绿但界面必崩 |
| 已补措施 | 冒烟测试增加"真实调用一次主视图组件"，同类初始化错误以后会被 `npm test` 捕获 |
| 当前状态 | 已修复，但**需要你重启 DSH Desktop 才生效** |

## 二、开发过程中犯的错误与返工（P1）

### P1-1 用 PowerShell 改源码导致文件编码损坏（M2 期间）

- 操作：用 `Set-Content -Encoding utf8` 批量替换 `lib/index.js` 中的一行。
- 后果：PowerShell 以 GBK 读取 UTF-8 文件再写回，**所有中文注释/文案变成乱码**，文件不可用。
- 恢复：`git checkout -- lib/index.js` 回滚到 M1 提交，重新逐条应用 M2 的 6 处编辑。
- 代价：一次完整返工 + 一轮测试重跑。
- 结论：**源码一律用 edit/write 工具改，禁止用 shell 文本重写命令**（这条之前已经踩过一次 Java BOM 的坑，这次又踩了编码的坑）。

### P1-2 配置预设与默认值不自洽

- 现象：默认模块集（提醒关、AI 关）与 `full` 预设定义不一致，导致默认档位显示为 `custom`。
- 修复：`full` 预设改为"除 AI 外全部模块"，提醒默认改为开；档位统一由实际模块集反推。
- 影响：只是显示与语义问题，未影响数据。

### P1-3 数据模型改动后测试断言滞后

- 改 `title`/`body` 后，M8 的 CSV 表头断言、M9 的搜索字段断言仍按旧模型写，测试一度失败。
- 已同步更新断言，但说明**模型变更时没有一次性同步测试**，是流程缺口。

### P1-4 AI 工具 schema 与新模型冲突

- `todo_add` 的 `required: ['content']` 与"标题优先（title）"的新模型冲突：只传 title 会被 schema 拦截。
- 已移除 `required`，改由 `store.add` 统一校验（title 或 content 至少一个）。
- 副作用：schema 变宽松，空参数会在执行期报错而不是被框架拦截。

### P1-5 需求文档与实现出现偏差（部分已在文档第 13 节注明）

| 项 | 文档 | 实际 | 状态 |
|---|---|---|---|
| 提醒默认 | 关 | 开（为让"完整"档位自洽） | 已在文档记录 |
| 虚拟列表 | 可选虚拟化 | 分批渲染 + 滚动加载 | 已在文档记录 |
| 描述字段 | `desc` | 实际用 `title` + `body` | **未更新文档** |
| AI 工具 | 默认关 | 默认关（符合），但你原有的"记住/待办"工作流随之停用 | 需你确认是否需要默认开 |
